# Milestone 11: Painel Admin, RBAC e Refatoração de UI

## Overview
O Milestone 11 introduz controle de acesso baseado em funções (RBAC), criando um isolamento claro entre visitantes não autenticados, clientes da plataforma e operadores do sistema (Admins). O objetivo é limpar a interface do candidato, removendo controles de infraestrutura, e consolidá-los em um novo painel administrativo seguro.

---

## Requisitos Funcionais

### 1. Fase 40: Isolamento de Estado e Limpeza UI Cliente
- [x] **REQ-1101**: Corrigir a exibição de dados pré-carregados (ex: "Moacir Neto") quando a sessão for nula. Usuários não autenticados (`GUEST`) devem ver a interface em estado zerado/público.
- [x] **REQ-1102**: Adicionar Call-to-Actions (CTAs) convidando visitantes para as rotas `/login` ou `/register` nas áreas restritas.
- [x] **REQ-1103**: Remover todos os controles e métricas de infraestrutura do painel do cliente.
- [x] **REQ-1104**: Manter na interface do cliente apenas: `Explorador de Vagas`, `Vagas Recomendadas (Match IA)`, `Meu Perfil / CV` e `Planos & Preços`.

### 2. Fase 41: Implementação RBAC (Roles)
- [x] **REQ-1105**: Estender o modelo de usuário/autenticação para incluir a propriedade `role`.
- [x] **REQ-1106**: Definir e implementar papéis claros: `GUEST` (Visitante), `CANDIDATE` (Cliente Free/Pro) e `ADMIN` (Operador do sistema).
- [x] **REQ-1107**: Criar middlewares/guards para proteger rotas e componentes da interface baseados na role do usuário.

### 3. Fase 42: Criação do Painel do Administrador (`/admin`)
- [x] **REQ-1108**: Criar a rota isolada `/admin` e layout correspondente, acessível exclusivamente por usuários com `role === 'ADMIN'`.
- [x] **REQ-1109**: Migrar os botões operacionais da Navbar (*Status dos Scrapers*, *Logs & Auditoria*, *Purgar Não-Tech*, *Sincronizar*) para o painel Admin.
- [x] **REQ-1110**: Garantir que as APIs de infraestrutura e administração rejeitem requisições de usuários que não possuem role `ADMIN`.

# Scoped Requirements: Buscavag v6.0 - Sanitização e Triagem Inteligente de Vagas

## Status: ✅ Completed (All requirements fulfilled)

## Contexto e Motivação

Os scrapers coletam vagas de 26+ fontes sem filtragem de relevância no ponto de entrada.
Isso resultava em vagas completamente fora da área de tecnologia (pedreiro, motorista, vigilante, etc.)
sendo persistidas no banco e ocupando a interface. Este milestone implementou três camadas de defesa.

---

## Requisitos Funcionais

### 1. Blacklist de Cargos Não-Tech (Filtro de Ingestão)

- [x] **FIL-10**: Blacklist no Pipeline — Validado: Checagem pré-ingestão com termos configuráveis em `src/config/jobFilters.ts`.
- [x] **FIL-11**: Tech Whitelist no Pipeline — Validado: Whitelist de termos técnicos obrigatórios no título.
- [x] **FIL-12**: Logging de Rejeições — Validado: Logs com motivos `[FILTRO BLACKLIST]` e `[FILTRO WHITELIST]` e sumário estatístico ao final do pipeline.

### 2. Trava da Hermes IA (Triagem Automática Aprimorada)

- [x] **SCR-10**: Trava de Score Zero — Validado: `stackScore === 0` e título sem termo da whitelist força `overallScore = 0` e `isJuniorFullStack = false`.
- [x] **SCR-11**: Status Automático "Descartada" — Validado: Vagas com `isJuniorFullStack = false` recebem status `'rejected'` ao invés de `'pending'` no banco.

### 3. Script de Purga do Banco de Dados (Database Cleanup)

- [x] **DB-10**: Rota de Purga — Validado: `POST /api/jobs/purge-non-tech` implementada e funcional.
- [x] **DB-11**: Método no Repositório — Validado: `JobRepository.purgeNonTech()` remove vagas de cargos não-tech via SQL batch.
- [x] **DB-12**: UI para Purga (Navbar ou Settings) — Validado: Botão "Purgar Não-Tech" na Navbar Desktop e Mobile Floating Dock com confirmação SweetAlert2 e SyncToast reativo.
